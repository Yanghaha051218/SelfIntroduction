# 个人资料问答 Agent

## 首版范围

支持 `.txt` / `.md` / `.docx` / `.pdf` 资料。上传后在本机提取为文本，再检索相关段落；调用模型基于资料回答并展示来源。无相关资料时明确回答未找到，避免编造个人经历。服务只监听 `127.0.0.1`。原始 DOCX / PDF 文件不会保留。

## 启动

```sh
python3 app.py
```

打开 <http://127.0.0.1:8000>。可在设置环境变量后启用生成式回答：

```sh
export OPENAI_API_KEY="你的 API 密钥"
python3 app.py
```

PDF 提取需要系统安装 Poppler 的 `pdftotext` 命令；DOCX 和文本文件不需要额外依赖。扫描版 PDF 图片没有文字层，当前不会做 OCR。

可用 `OPENAI_MODEL` 指定模型。默认资料保存在项目的 `data/documents/`；设置 `PERSONAL_AGENT_DATA` 可改到其他本机目录。没有 API 密钥时会显示检索到的原文，不生成总结。

设置密钥后，只有检索到的片段和当前问题会发送到 OpenAI Responses API，并请求 `store:false`。这仍受 API 账号的数据控制和保留政策约束；使用前请确认适合存放和发送这些资料，详见 [API 数据控制说明](https://platform.openai.com/docs/models/default-usage-policies-by-endpoint)。

## 阶段规划与自审

1. **本地问答闭环（完成）** — 资料导入、关键词检索、来源回答、删除资料。自审：服务绑定本机、限制文件类型和体积、模型只收到命中片段；中文检索使用简单字符/双字匹配，语义改写可能漏召回。
2. **常见文档导入（完成）** — DOCX 用标准库解析，PDF 用本机 `pdftotext`，不上传原始文件。扫描件 OCR 需有真实样本后再选方案。
3. **检索质量（合成自检完成）** — 多部分问题可从同一文件取回多个相关段落；相同相关度按文件名稳定排序。自检覆盖“教育背景 + 项目经历”和并列命中。真实资料和常见问题尚未提供，暂不能评估实际召回；只有关键词漏召回明显时再引入向量检索。
4. **回答质量与管理（首轮自审完成）** — 自检确认请求只包含检索段落、提示模型只依据资料并解析带来源回答；界面补了空状态、表单标签、删除确认和网络错误提示。实际模型输出和引用质量仍需配置 API 密钥并用真实资料评估；再根据失败案例决定是否补管理功能。
5. **安全发布** — 若要给他人访问，再添加身份验证、访问控制、备份/删除策略及部署；首版不监听局域网或公网。

每阶段按实际样本自审“是否命中正确资料、回答是否能追溯来源、资料是否越权暴露”，达不到再做下一项改进，避免预先搭建不需要的基础设施。
